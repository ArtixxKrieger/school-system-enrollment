🎓 Enrollment Lifecycle - Complete Testing Guide

This guide provides step-by-step instructions to test all enrollment lifecycle scenarios.

📋 Setup & Database Check

Step 1: Verify MySQL database connection
mysql -u root enrollment -e "SELECT COUNT(*) as courses FROM courses; SELECT COUNT(*) as curriculum FROM curriculum;"
Expected: Both queries should return counts. If curriculum is 0, run migrations first.
Step 2: Check enrollment_settings configuration
mysql -u root enrollment -e "SELECT * FROM enrollment_settings WHERE id = 1;"
Expected: Should show enrollment settings with auto_progression and strict_enrollment_windows flags

📝 TEST 1: New Applicant Pre-Registration (Regression Test)

Purpose: Verify new applicant flow still works correctly (not affected by re-enrollment logic)

Step 1: Pre-register a new student via web form
  • Go to: http://localhost/enrollment/pre_reg.php
  • Fill form with sample data (Name, Email, Phone, Course, etc.)
  • Submit and note the Pre-Reg Number (e.g., PRE-12345)
Step 2: Query database to verify enrollee created
mysql -u root enrollment -e "SELECT * FROM enrollees WHERE status='pre-registered' ORDER BY id DESC LIMIT 1;"
Expected:
  • status = 'pre-registered'
  • enrollment_type = 'new'
  • year_level = 1
  • existing_student_id = NULL
Step 3: Approve the pre-registration in UI
  • Go to: http://localhost/enrollment/superadmin/enrollees.php
  • Find and click "Approve" for the new enrollee
Step 4: Query database to verify student created
mysql -u root enrollment -e "SELECT id, student_id, year_level, current_semester, status, progression_status FROM students WHERE status='active' AND progression_status='enrolled' ORDER BY id DESC LIMIT 1;"
Expected:
  • year_level = 1
  • current_semester = 1
  • status = 'active'
  • progression_status = 'enrolled'
Step 5: Verify subjects assigned
mysql -u root enrollment -e "SELECT COUNT(*) as subjects FROM student_enrolled_subjects ses INNER JOIN curriculum cu ON cu.id=ses.curriculum_id WHERE ses.student_id=(SELECT id FROM students WHERE status='active' ORDER BY id DESC LIMIT 1) AND cu.year_level=1 AND cu.semester=1;"
Expected: subjects > 0 (some subjects should be assigned)

📝 TEST 2: End 1st Semester → Re-enroll → Student in 2nd Semester

Purpose: Verify semester progression within same year works correctly

Step 1: Create or find a 1st year, 1st semester student
mysql -u root enrollment -e "SELECT id, student_id, year_level, current_semester, status FROM students WHERE year_level=1 AND current_semester=1 AND status='active' LIMIT 1;"
Expected: At least one such student (use Pre-Reg from TEST 1 if available)
Step 2: End 1st semester in UI
  • Go to: http://localhost/enrollment/superadmin/student.php
  • Find the student
  • Click "End 1st Sem" button
  • Note: This calls /api/student_year_progression.php with action=trigger_semester_end, semester=1
Step 3: Verify student moved to semester 2 with pending_progression
mysql -u root enrollment -e "SELECT id, student_id, year_level, current_semester, progression_status, status FROM students WHERE year_level=1 AND current_semester=2 ORDER BY id DESC LIMIT 1;"
Expected:
  • year_level = 1 (unchanged)
  • current_semester = 2
  • progression_status = 'pending_progression'
  • status = 'active'
Step 4: Verify returning enrollee created
mysql -u root enrollment -e "SELECT * FROM enrollees WHERE enrollment_type='returning' AND status='pending' ORDER BY id DESC LIMIT 1;"
Expected:
  • enrollment_type = 'returning'
  • status = 'pending'
  • existing_student_id = (student_id from previous step)
  • year_level = 1
Step 5: Re-enroll in UI (Approve the returning enrollee)
  • Go to: http://localhost/enrollment/superadmin/enrollees.php
  • Go to "Returning" tab
  • Click "Re-enroll" button for the student
  • This calls /api/enrollees_approve.php with enrollee_id
Step 6: Verify student is now enrolled in 2nd semester
mysql -u root enrollment -e "SELECT id, student_id, year_level, current_semester, progression_status, status FROM students WHERE year_level=1 AND current_semester=2 AND progression_status='enrolled' ORDER BY id DESC LIMIT 1;"
Expected:
  • current_semester = 2
  • progression_status = 'enrolled'
  • status = 'active'
Step 7: Verify subjects assigned for 2nd semester
mysql -u root enrollment -e "SELECT COUNT(*) as subjects FROM student_enrolled_subjects ses INNER JOIN curriculum cu ON cu.id=ses.curriculum_id WHERE ses.student_id=(SELECT id FROM students WHERE current_semester=2 AND progression_status='enrolled' ORDER BY id DESC LIMIT 1) AND cu.year_level=1 AND cu.semester=2;"
Expected: subjects > 0

📝 TEST 4: End 2nd Semester for 4th Year → Graduation

Purpose: Verify 4th year 2nd semester students graduate (don't get re-enrollee)

Step 1: Create a 4th year, 2nd semester student
mysql -u root enrollment -e "INSERT INTO students (student_id, pre_reg_number, first_name, last_name, email, phone, course_id, year_level, status, progression_status, is_account_active, current_semester, current_academic_year, enrollment_date) VALUES (CONCAT('TST4-', UNIX_TIMESTAMP()), CONCAT('PRE-4-', UNIX_TIMESTAMP()), 'Test4Year', 'Senior', CONCAT('test4yr_', UNIX_TIMESTAMP(), '@test.local'), '09100000004', (SELECT id FROM courses LIMIT 1), 4, 'active', 'enrolled', 1, 2, '2025-2026', NOW()); SELECT LAST_INSERT_ID();"
Expected: A student ID is returned (e.g., 123). Note this ID for next steps.
Step 2: Verify student is in database as 4th year, semester 2
mysql -u root enrollment -e "SELECT id, year_level, current_semester, status FROM students WHERE year_level=4 AND current_semester=2 AND status='active' ORDER BY id DESC LIMIT 1;"
Step 3: End 2nd semester for this 4th year student
  • Go to: http://localhost/enrollment/superadmin/student.php
  • Find the 4th year, 2nd semester student
  • Click "End 2nd Sem" button
Step 4: Verify student status changed to 'graduated'
mysql -u root enrollment -e "SELECT id, student_id, year_level, current_semester, status, graduated_at, is_account_active FROM students WHERE year_level=4 AND status='graduated' ORDER BY id DESC LIMIT 1;"
Expected:
  • status = 'graduated'
  • graduated_at = NOT NULL (current timestamp)
  • is_account_active = 0
Step 5: Verify NO returning enrollee created for graduated student
mysql -u root enrollment -e "SELECT COUNT(*) as count FROM enrollees WHERE enrollment_type='returning' AND year_level=4 AND status='pending';"
Expected:
  • count = 0 (no re-enrollee should be created for year 4)
Step 6: Verify graduated student appears in Records
  • Go to: http://localhost/enrollment/superadmin/records.php
  • Should see the 4th year student in the "Graduated" section
Step 7: Verify via API
curl -s "http://localhost/enrollment/api/records_list.php" | grep -i "graduated"
Expected: Should show the graduated student in the response

📝 TEST 5: Idempotency - Re-run Single Approval

Purpose: Verify approving the same enrollee twice is safe

Step 1: Create a pre-registration enrollee
mysql -u root enrollment -e "INSERT INTO enrollees (pre_reg_number, first_name, last_name, email, phone, course_id, year_level, status, enrollment_type, application_date) VALUES (CONCAT('IDEM-', UNIX_TIMESTAMP()), 'Idempotent', 'Test', CONCAT('idem_', UNIX_TIMESTAMP(), '@test.local'), '09199999999', (SELECT id FROM courses LIMIT 1), 1, 'pre-registered', 'new', NOW()); SELECT LAST_INSERT_ID();"
Expected: An enrollee ID is returned (e.g., 456). Note this ID.
Step 2: Approve the enrollee first time (via UI or API)
  • Via UI: Go to enrollees, click Approve
  • Via cURL:
    curl -X POST "http://localhost/enrollment/api/enrollees_approve.php" \ -H "Content-Type: application/json" \ -d '{"enrollee_id": 456, "admin_id": 1}'
Expected: Response with ok: true
Step 3: Attempt to approve the SAME enrollee AGAIN
curl -X POST "http://localhost/enrollment/api/enrollees_approve.php" \ -H "Content-Type: application/json" \ -d '{"enrollee_id": 456, "admin_id": 1}'
Expected: Response with ok: false and error message "Enrollee not found or already processed" (because status is now "approved")
Step 4: Query database to verify only ONE student record exists
mysql -u root enrollment -e "SELECT COUNT(*) as count FROM students WHERE email LIKE 'idem_%';"
Expected: count = 1 (only one student created, not duplicated)

📝 TEST 6: Idempotency - Re-run Bulk Approval

Purpose: Verify bulk approval doesn't duplicate-process already-approved enrollees

Step 1: Create multiple pre-registration enrollees
mysql -u root enrollment -e "INSERT INTO enrollees (pre_reg_number, first_name, last_name, email, phone, course_id, year_level, status, enrollment_type, application_date) VALUES (CONCAT('BULK-1-', UNIX_TIMESTAMP()), 'Bulk', 'One', CONCAT('bulk1_', UNIX_TIMESTAMP(), '@test.local'), '09191111111', (SELECT id FROM courses LIMIT 1), 1, 'pre-registered', 'new', NOW()), (CONCAT('BULK-2-', UNIX_TIMESTAMP()), 'Bulk', 'Two', CONCAT('bulk2_', UNIX_TIMESTAMP(), '@test.local'), '09192222222', (SELECT id FROM courses LIMIT 1), 1, 'pre-registered', 'new', NOW()); SELECT GROUP_CONCAT(id) as ids FROM enrollees WHERE pre_reg_number LIKE 'BULK-%' AND status='pre-registered' ORDER BY id DESC LIMIT 2;"
Expected: Two enrollee IDs returned (e.g., 457, 458)
Step 2: Bulk approve these enrollees (first time)
curl -X POST "http://localhost/enrollment/api/enrollees_bulk_approve.php" \ -H "Content-Type: application/json" \ -d '{"enrollee_ids": [457, 458], "admin_id": 1}'
Expected: Response with ok: true and approved_count: 2
Step 3: Attempt bulk approve AGAIN with same enrollee IDs
curl -X POST "http://localhost/enrollment/api/enrollees_bulk_approve.php" \ -H "Content-Type: application/json" \ -d '{"enrollee_ids": [457, 458], "admin_id": 1}'
Expected: Response with ok: true but approved_count: 0 (no new approvals) or errors for each enrollee
Step 4: Verify database shows only 2 student records (not 4)
mysql -u root enrollment -e "SELECT COUNT(*) as count FROM students WHERE email LIKE 'bulk%';"
Expected: count = 2 (not duplicated)

🐛 Troubleshooting

Issue: Curriculum not found for year/semester Solution: Run database migrations first:
mysql -u root enrollment < database_migration.sql mysql -u root enrollment < database_migration_reenroll.sql
Issue: No courses found in database Solution: Create a test course first:
mysql -u root enrollment -e "INSERT INTO courses (code, name, description) VALUES ('TEST', 'Test Course', 'For testing');"
Issue: Enrollment windows blocking approval Solution: Disable strict enrollment windows in settings:
mysql -u root enrollment -e "UPDATE enrollment_settings SET strict_enrollment_windows = 0 WHERE id = 1;"
Issue: Permission denied when calling API Solution: Ensure you're logged in as admin. Check in config/auth.php that session permissions are granted.
